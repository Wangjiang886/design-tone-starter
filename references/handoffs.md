# 跨智能体交接模板

用实际项目内容填写下面模板，删去不适用项。交接前列出真正附上的文件；发送文字不能代替传图或传视频。缺少自动接口时由用户手动发送，当前流程记录待回复。

## 1. 素材是否找对：给 Codex／豆包

```text
你负责第二视角的素材复核。请先看实际附件，再回答。

项目目标与受众：
用户选定的方向：
参考链接与其中要保留的特征：
必要内容与明确限制：

附件列表：素材 ID / 文件名 / 用于哪个页面或镜头 / 来源。

请逐项回答：
1. 文件里实际是什么，与预期用途是否匹配？请给可定位的画面依据。
2. 信息、结构、身份或细节有没有明显找错？读不清、未看到的内容单列。
3. 哪些可用、哪些需核实、哪些不适合？缺的材料应补什么？

请按“素材 ID｜实际观察｜用途匹配｜问题｜建议”输出。
没有拿到附件时请直接说明，不推断你已经看过。
```

保存真实回复到 `02_过滤库/素材复核反馈_<版本>.md`，筛选记录引用它。主制作方结合原始目标决定如何采用建议，最终创作选择交用户。

## 2. 给 Claude／DeepSeek 的制作交接

```text
请制作用户已经选择的网页视觉方案。

项目根目录与当前阶段：
已确认的简报与定调文件：
本轮只实现的页面/段落和目标：
已确认文案（如适用）：
已通过素材 ID、用途与原件路径：
第二视角反馈及需要保留的修正：
用户明确限制：

交付：可打开的网页预览、源码定位、本轮改变和待决定项。
视频制作阶段默认静音，不导出 MP4，不合成 TTS/音乐/音效。
先保留已通过部分，别在本轮重做整套。
```

## 3. 给 Codex／豆包的预览审查

```text
请按本轮目标审查实际预览和给出的源码/附件。

当前版本与预览：
本轮目标与用户验收依据：
需要审查的区块或时间段：
已通过、应保留的部分：

指出有实际依据的问题、影响和最小修改建议。
请区分：实际看到的画面、源码推断、尚未验证的运行表现。
无法打开预览或未收到附件时直接说明。
```

该结果是审查意见。技术通过或第二智能体认可不自动等于用户接受。

## 4. 视觉定稿后：给豆包的 TTS 与音效交接

```text
请基于已经确认的最终画面安排声音。

最终视觉版本：
实际可访问的预览或附上的画面材料：
确定的完整文案：
受众、语种、声音身份、语气和节奏：
专有词读音、需要保留的停顿：

按镜头/段落填写：
起止时间或画面位置｜画面发生什么｜口播原文｜重音/语气/停顿｜音效触发点

请分别提供口播与音效；用户没有要求时不添加音乐。
如当前入口能生成文件，请交代实际文件及规格；只能给声音方案时请明确说明。
```

把声音交接单放 `04_最终方案/声音交接.md`。获得用户要求的声音文件后再按该任务约定存入成品；只生成交接单时标 `handoff_ready`，不写音频已生成。

本机 `localhost` 对远端不可访问。优先用用户实际提供的截图、时间说明或片段；仍不足以判断节奏时说明缺口并取得需要的材料。不要仅凭网页文字制作声画同步结论，也不要为交接自动公开部署私有项目。
