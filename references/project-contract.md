# 项目与进度约定

## 项目结构

```text
项目名/
├─ 00_核心分区/
│  ├─ 00_从这里开始.md
│  ├─ 01_项目简报.md
│  ├─ 02_定调方案.md
│  ├─ 03_步骤与目标.md
│  ├─ 04_素材清单.csv
│  └─ 进度.json
├─ 01_素材库/
│  ├─ 图片/
│  ├─ 视频/
│  ├─ 文档/
│  └─ 链接/
├─ 02_过滤库/
│  ├─ 已通过/
│  ├─ 待核实/
│  └─ 未采用/
├─ 03_制作区/
├─ 04_最终方案/
└─ 05_成品/
```

初始化工具只创建缺少的目录和导航文件，保留现有文件内容和进度；它不收集素材、不安装软件、不启动服务，也不自动推进阶段。首次选择单独的项目目录，避免把整个桌面或资料盘当作项目。

若已有同名路径是文件、目录类型冲突或计划路径含符号链接/联接目录，先报告冲突。不要覆盖、删除或绕过保护。没有 Python 时也遵守同样规则。

## 核心记录怎么写

- **简报**：方向、目标观众、用途、参考、最终大致样子、网页/视频类型、必要尺寸和时长。按“已定／建议／待问”分开记录。
- **定调方案**：参考里能观察到的特征、用户选择、变更点和验收依据。写“低饱和冷蓝、单一主光、文字不遮主物体”等可判断的特征。
- **步骤与目标**：每一步的目标、所需输入、落盘产物和下一步。修改范围后同步调整清单，不让旧任务继续执行。
- **素材清单**：一个素材一个 ID；保留原来源链接、作者/来源、原件相对路径、用途、筛选状态、复核者和复核记录。未读内容标“未读”，未找到的项标“缺口”。

链接类素材可以保存来源 URL 与实际摘录、读取时间和使用目的；不要把网页标题当作完整阅读。遇到临时下载地址时另存原始来源页，分享时不夹带账号、签名 URL 或凭证。

## 过滤库如何工作

过滤库保存筛选记录，例如 `已通过/M-003.md`，内容包含原件路径、用于哪个模块、采用理由和复核依据。原文件留在素材库。

“已通过”指当前用途通过，不表示所有用途都适合；“待核实”保留问题和需要补的证据；“未采用”记录原因以免反复找同一份资料。没有用户要求时不复制多份大素材，也不自动清理原件。

## 阶段与真实状态

`进度.json` 的 `stage` 使用以下值：

| 值 | 当前在做什么 | 进入下一步的依据 |
|---|---|---|
| `brief` | 询问方向、参考、预期样子 | 用户选定方向 |
| `plan` | 分析参考、文案和步骤、列资料清单 | 方案与清单可执行，用户选择下一步 |
| `collect` | 收集与登记资料 | 必要材料齐备或用户明确缩小范围 |
| `review` | 第二视角核对实际素材 | 真实回复、用户自行审核，或用户明确选择暂缓复核 |
| `produce` | 制作第一版网页视觉 | 有实际预览入口与对应源码 |
| `iterate` | 看预览并返工 | 用户确认该视觉版本 |
| `final` | 整理最终方案与交付 | 最终入口、版本和资料引用可定位 |
| `audio-handoff` | 向豆包交接声音需求 | 用户要求的交接或声音文件完成 |
| `done` | 本次约定交付完成 | 所要求事项均已完成；没有音频需求则不等音频 |

`stage` 表示在做什么，详细检查结果分别写进 `second_review`、`preview`、`visual_approved` 和 `audio`，不要用一个“完成”覆盖它们。目录或文件创建成功不自动改变任何验收状态。

工具初始化的 `project_type` 默认为 `undecided`，选择后再改 `web` 或 `video`。视频是否先写文案由用户选择记录在简报；网页没有口播需求时 `copy_status` 可写 `not_needed`。

`second_review.status` 可用 `not_started/pending/received/user_reviewed/deferred_by_user`。写 `received` 时还需 reviewer 与实际反馈文件路径；用户选择暂缓时记录原话和仍存的缺口，不伪装成复核通过。

`preview.gpu_status` 可用 `not_verified/checked`。写 `checked` 时在检查记录说明依据和机器环境，不能据“页面能打开”修改此字段。

`audio.status` 可用 `not_requested/handoff_ready/sent/received`，provider 固定为 `doubao`。没有用户要求的实际调用，不从交接单直接跳到已收到音频。

## 每次结束前

更新本轮已经决定的事项、当前阶段、待补材料、实际文件/预览位置、用户未答的 1—3 个问题和下一步。关闭聊天前无需重复征求已取得的授权；需要用户作设计选择时停在该选择点，不能把沉默视作确认。

若制作平台将源码保存在自己的项目目录，`preview.production_root` 记录真实位置，制作区保存索引和迭代记录即可。不要移动平台数据库或内部目录以迎合分区。
